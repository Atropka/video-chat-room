# video-chat-room

MVP группового видеочата на React + Vite + Socket.io + WebRTC mesh.

## Возможности

- комнаты без регистрации и базы данных;
- идентификатор комнаты в URL;
- максимум 4 участника в комнате;
- одинаковые имена разрешены;
- текстовый чат с историей в памяти комнаты;
- системные сообщения о входе и выходе;
- независимое управление микрофоном и камерой;
- выбор камеры, микрофона и аудиовыхода, если браузер поддерживает `setSinkId()`;
- WebRTC mesh: отдельное P2P-соединение между каждой парой участников;
- сервер используется только для комнат, чата, состояния media и WebRTC signaling;
- публичный Google STUN, TURN не используется;
- выход из комнаты и повторный вход;
- адаптивная вёрстка для узких экранов.

## Стек

- Frontend: React 18, Vite, TypeScript, React Router 6, Socket.io Client.
- Backend: Node.js, Express 5, Socket.io 4, TypeScript.
- Media: `getUserMedia()`, `RTCPeerConnection`, `addTrack()`, `replaceTrack()`.
- Хранилище: только память процесса Node.js. После перезапуска сервера комнаты и сообщения исчезают.

## Требования

- Node.js 18+.
- Современный браузер с поддержкой WebRTC и `getUserMedia()`.
- Для локальной разработки frontend запускается через Vite, backend — через Node.js.

## Установка

Из корня проекта:

```bash
npm install
```

Проект использует npm workspaces, поэтому зависимости `client` и `server` устанавливаются одной командой.

```bash
npm --prefix server  install
npm --prefix client  install
```

## Разработка

Запустить frontend и backend одновременно:

```bash
npm run dev
```

Или отдельно:

```bash
npm run dev:server
npm run dev:client
```

По умолчанию:

- frontend: `http://localhost:5173`
- backend: `http://localhost:3000`
- health check: `http://localhost:3000/health`

Vite проксирует `/socket.io` и `/health` на backend.

Если возникают трудности с запуском frontend, можно попробовать на отдельный хост

```bash
npm --prefix client run dev -- --host 127.0.0.1
```

## Type checking

Проверить TypeScript-код frontend и backend:

```bash
npm run typecheck
```

## Production build

Собрать frontend и backend:

```bash
npm run build
```

После успешной сборки Vite создаёт `client/dist`.

Backend автоматически обнаруживает `client/dist`, раздаёт его как статические файлы и отдаёт SPA fallback для маршрутов вроде `/room/<roomId>`.

Запуск production-сервера:

```bash
npm start
```

Порт задаётся переменной `PORT`, по умолчанию `3000`.

Пример:

```bash
PORT=3000 npm start
```

## WebRTC

Используется mesh-топология: при 4 участниках каждый браузер поддерживает отдельное `RTCPeerConnection` с каждым из трёх остальных участников.

Сигналинг выполняется через Socket.io:

- `offer`;
- `answer`;
- `ice-candidate`.

Для каждой пары начальный offer инициирует одна сторона по детерминированному правилу `selfId < peerId`. Это не использует renegotiation для обычного включения/выключения камеры.

Локальные tracks добавляются через `addTrack()`. Переключение устройства выполняется через `replaceTrack()` без пересоздания peer connection.

Камера запрашивается с целевыми параметрами 1280×720 и до 30 FPS. Фактический режим выбирает браузер и устройство.

При выключении камеры video track останавливается и удаляется из локального MediaStream; sender получает `null`. При повторном включении камера запрашивается снова.

Используется только публичный STUN:

```text
stun:stun.l.google.com:19302
```

TURN-сервер отсутствует, поэтому в сетях, где прямое P2P-соединение невозможно, соединение может не установиться.

## Комнаты и ограничения

- `roomId`: 6–32 символа, `A-Z`, `a-z`, `0-9`, `_`, `-`.
- Имя: 1–30 символов, латиница/кириллица, цифры, пробелы и `-`.
- Сообщение чата: 1–1000 символов после trim.
- Максимум участников: 4.
- Если комнаты с указанным ID ещё нет, она создаётся при первом успешном входе.
- При заполненной комнате сервер отклоняет вход с кодом `ROOM_FULL`.
- После выхода последнего участника комната удаляется из памяти.

## Обработка ошибок

Предусмотрены отдельные сценарии для:

- отсутствующей камеры или микрофона;
- запрета доступа к устройствам;
- недоступности устройства;
- недоступного Socket.io/backend;
- заполненной комнаты;
- отсутствующей поддержки `RTCPeerConnection`;
- выхода пользователя;
- потери локального media track.

При ошибке подключения к серверу или заполненной комнате пользователь не остаётся в активном RoomView: ошибка передаётся обратно на prejoin.

## Тестирование

Backend содержит TypeScript/Node.js tests для:

- валидации room ID, имени и сообщений;
- операций `roomStore`;
- Socket.io сценариев комнат, чата, media state и ограничения в 4 участника.

Запуск:

```bash
npm test
```

Перед релизом рекомендуется также выполнить ручной acceptance-прогон:

1. Создание новой комнаты.
2. Вход по ссылке.
3. Несуществующий `roomId`.
4. Одинаковые имена.
5. 1–4 участника.
6. Попытка входа 5-го участника.
7. WebRTC на 4 участниках.
8. Включение/выключение камеры и микрофона.
9. Смена устройств.
10. Чат и системные сообщения.
11. Перезагрузка страницы.
12. Выход и повторный вход.
13. Недоступный сервер.
14. Неподдерживаемый WebRTC.

## Ограничения MVP

- нет регистрации и авторизации;
- нет постоянного хранения комнат и сообщений;
- нет истории после перезапуска сервера;
- нет TURN;
- нет автоматического reconnect Socket.io;
- media не проходит через сервер;
- качество WebRTC зависит от браузеров, устройств и сетевой топологии.
